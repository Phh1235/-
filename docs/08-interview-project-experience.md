## 一、五句话，让面试官一眼看出"这项目不是跟着教程敲的"

> 用法：自我介绍或项目开场时挑 2~3 句说，别一次全倒出来。

1. **它是双栈闭环，不是两个各写各的服务**：Java 管状态机、事务、幂等、鉴权和补偿，Python 做无状态执行器；中间用 Feign 下发 + HMAC 签名回调打通，长任务异步不阻塞请求。
2. **它敢说"模型不参与算钱"**：价格只能来自原文正则抽取并回查，打分是确定性加权公式，报告里的每个数字都要能对回事实表，对不上整段丢弃——所以它不会编报价。
3. **它把"失败"当一等公民**：任务有状态机和事件溯源，非法迁移直接 409，SSE 断线可回放，回调有防重放和幂等，下游挂了有定时补偿。
4. **它有真 bug 复盘**：`@Async` 读不到未提交事务导致任务永久 QUEUED，最后用 `TransactionSynchronization.afterCommit` 修掉；异步回写覆盖用户"取消"，改成带条件的字段更新。
5. **它有可复现的评测**：40 条需求测试集 + 7 条对抗用例，召回率、字段填充率、抽检准确率一键出 Markdown 报告，而且能主动说明这些 100% 的口径边界在哪。

## 二、简历版（直接贴）

**项目名称**：Procure Agent —— 采购比价与供应商尽调 Agent（双栈）

**担任角色**：Java 后端开发 / 独立开发（含 Python Agent 侧与前端演示页）

**项目描述**：
面向中小采购场景的"比价 + 尽调"C 端工具型项目。输入一条采购需求（品类、规格、数量、预算、交付地），系统自动完成需求解析、候选供应商召回、公开报价页只读取证、字段清洗归一化、确定性打分与风险识别，输出可审计的比价表与推荐结论，全流程七阶段进度通过 SSE 实时推送。
采用双栈架构：Java 21 + Spring Boot 3 + MyBatis-Plus + MySQL/Flyway 构建有状态业务中台（JWT 鉴权、注解式限流、任务状态机、结果持久化、报告与 CSV 导出、定时补偿）；Python FastAPI + LangChain(LCEL) 实现无状态 Agent 执行器（正则优先 + 大模型兜底的抽取、SSRF 白名单抓取、提示词注入隔离、输出脱敏）。两端通过 OpenFeign 下发任务、HMAC-SHA256 签名回调回传结果，配合时间戳窗口、nonce 唯一索引与 eventId 幂等保证回调不可伪造、不可重放。
设计"数据闸 / 计算闸 / 文本闸"三层反编造机制，并为每条数据标注来源 URL、抓取时间与置信度，无法核实的字段显式标记"待人工核实"；提供 mock 数据模式，断网可完整演示。

**项目业绩**：
- 独立完成 **9 张表 / 20+ REST 接口 / 7 阶段流水线**，Java 侧 2.6k 行、Python 侧 1.4k 行代码；
- 测试覆盖 **Java 45 项 + Python 33 项**，全部通过；接口级测试基于 `MockMvc` + H2，Agent 侧全离线、结果可复现；
- 自建 **40 条评测集（覆盖 6 个品类）+ 7 条对抗用例**，供应商召回率、字段填充率、抽检准确率、黑名单识别率、报告结构完整率均达 **100%**（mock 数据真值同源，已在文档中说明口径边界）；
- 回调链路实现 **HMAC 验签 + ±5min 时间窗 + nonce 防重放 + eventId 幂等** 四重保护，异常路径全部有测试覆盖；
- 抓取侧实现 **SSRF 四重校验（协议/userinfo/IP 直连/域名白名单）+ 禁重定向 + 大小与频率上限**，并把"内网可达、DNS 重绑定挡不住"写进已知限制；
- 排查并修复 3 个线上级缺陷：异步线程读不到未提交事务（afterCommit）、异步回写覆盖取消状态（带条件更新）、"原价 ¥999 / 现价 ¥28.5" 抓错价（上下文权重打分）。

## 三、口述版

### 30 秒（自我介绍里带一句）

> 我做过一个双栈的采购比价 Agent：Java 侧负责需求单、供应商主数据、任务状态机和 SSE 进度，Python 侧用 FastAPI + LangChain 做无状态执行器，Feign 下发、HMAC 回调。核心设计是"模型只读文本、不参与算钱"——价格必须原文回查，打分走确定性公式，报告数字对不上事实表就丢弃。有 40 条离线评测集，指标一键出报告。

### 90 秒（"讲讲你最有代表性的项目"）

> 这个项目解决的是采购比价里最烦的两件事：找谁比、数据可不可信。
>
> 架构上我刻意做了**状态与执行分离**：Java 是有状态的编排器，管需求单、供应商主数据、任务状态机、JWT、限流、SSE 推送和结果持久化；Python 是无状态执行器，只做七件事——解析、召回、抓取、归一化、打分、风险、报告。这样可靠性归 Java，水平扩容归 Python。
>
> 两个关键设计。第一是**反编造**：模型输出的 schema 里根本没有价格字段，价格只能由正则从原文抽取，并且必须能回查到原文；总分是固定权重公式算出来的；报告正文里出现的数字如果对不上事实表，整段丢弃重写。
>
> 第二是**可观测与可回放**：每个阶段都落一条事件表再推 SSE，断线能回放，非法状态迁移直接 409；回调用 HMAC + 时间戳窗 + nonce + eventId 幂等四重保护。
>
> 过程中踩得最狠的坑是 `@Async` 下发任务时读不到未提交的事务，任务永远停在 QUEUED——最后用 afterCommit 注册解决。还有一次异步回写整个实体，把用户刚点的"取消"覆盖了，改成了带条件的字段更新。

## 五、追问预案（每题一句话）

| 追问 | 一句话答案 |
|---|---|
| 为什么不做多智能体？ | 决策权必须交给确定性打分器，多智能体只会让"为什么推荐它"变得不可复现。 |
| 为什么 Python 不管状态？ | 状态要事务、幂等、补偿、审计，这些是 Java 的强项；Python 无状态才能重启即恢复、水平扩容。 |
| 怎么保证不编报价？ | 三道闸：schema 无价格字段、公式算分、报告数字回查事实表。 |
| 回调怎么防重放？ | 时间戳 ±5 分钟 + nonce 唯一索引 + eventId 幂等 + 常量时间比较。 |
| SSE 怎么鉴权？ | EventSource 不能带 header，所以先换 60 秒一次性票据，票放 URL。 |
| 100% 指标可信吗？ | 只证明流水线正确（mock 真值同源），真实网页准确率要靠线上抽检，这点我写进了已知限制。 |
| 并发高了怎么办？ | 状态迁移改带条件 UPDATE + 影响行数判断，限流切 Redis，Python 侧多副本 + 任务队列。 |
| 和开源模板差在哪？ | 不做多智能体、不爬电商站、模型不算钱、有评测和回调安全——四条都是主动取舍。 |
